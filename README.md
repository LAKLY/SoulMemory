# SoulMemory

Kira — AI-ассистент с продвинутой долговременной памятью
(или KiraBot: Long‑Term Memory with Groq, FAISS and LLM consolidation)

🧠 Краткое описание
Kira – это диалоговый ассистент с полноценной «памятью», которая не просто хранит историю, а умеет:

🧩 извлекать факты из разговора и запоминать их атомарно;

🔁 дедуплицировать информацию (с помощью эмбеддингов);

🕓 учитывать время: эфемерные факты (TTL), поиск по временным срезам («за последний час», «вчера»);

🔗 строить семантические ассоциации между фактами;

⚖️ управлять доверием (trust), важностью (importance) и полезностью (usefulness) каждого факта;

🧹 автоматически забывать устаревшую или маловажную информацию;

🧠 консолидировать похожие факты через LLM (как «сборка мусора» в памяти);

❓ обнаруживать повторяющиеся вопросы пользователя;

😊 иметь настроение (mood), менять температуру ответа и переходить в «лаконичный режим»;

💬 проявлять инициативу – сама задавать вопросы о важной неподтверждённой информации.

Всё это работает локально (кроме вызовов LLM) и не требует дорогих серверов.

✨ Ключевые особенности
Модуль	Что делает
Извлечение фактов (LLM)	Из последних реплик диалога выделяются новые факты о пользователе и о Кире, с категориями user.*, kira.*, general.*.
Дедупликация	Сравнение эмбеддингов (косинусная близость), не сохраняются дубликаты. При конфликте заменяется менее достоверный факт.
Временные метки & TTL	Каждый факт получает timestamp. Эфемерные (importance < 0.4) удаляются через 2 часа.
Семантический поиск (FAISS)	Индекс FAISS с нормализованными косинусными векторами. Поддержка IDMap для прямого удаления.
Гибридный поиск	FAISS + BM25 + точное совпадение подстроки + ассоциации.
Фильтрация фактов перед ответом	LLM отбирает только релевантные факты из кандидатов – строгий контроль, чтобы не перегружать контекст.
Ассоциации	Если вспомнили один факт – автоматически подтягиваются связанные (хранятся в графовой структуре).
Временные срезы	Пользователь может спросить: «что ты узнала за последние 3 часа?», «вчера» и т.д.
Поиск повторных вопросов	Проверяется, не задавал ли пользователь похожий вопрос в последний час – чтобы не повторяться.
Динамическая важность	importance = base_importance + usage_bonus - age_penalty - idle_penalty.
Консолидация	Раз в сутки LLM объединяет семантически близкие факты (по категориям и глобально).
Режим «молчания» (laconic)	Если пользователь пишет очень коротко 3+ раза подряд – Кира переходит в режим ответа в 1‑2 предложения без вопросов.
Настроение (mood)	Меняется от слов пользователя и своих ответов. Влияет на температуру LLM и тон.
Инициатива	Если есть важный факт (importance > 0.8), а пользователь молчит больше минуты – Кира сама спрашивает о нём (не чаще 5 минут).
Асинхронное сохранение	Автосохранение каждые 5 минут (pickle), экспорт/импорт JSON.
Прогрев памяти	При старте перестраивает FAISS, обновляет важность, консолидирует и прогревает кеш эмбеддингов.
🛠 Технологический стек
Python 3.10+

Groq (LLM, модель qwen/qwen3-32b) – основной «мозг»

Sentence‑Transformers – эмбеддинги (intfloat/multilingual-e5-small)

FAISS – быстрый семантический поиск

BM25 (rank_bm25) – лексический поиск

Asyncio – асинхронные вызовы, фоновые задачи

Pickle / JSON – сериализация памяти

🚀 Быстрый старт
1. Клонируйте репозиторий
bash
git clone https://github.com/yourname/kira-memory-bot.git
cd kira-memory-bot
2. Установите зависимости
bash
pip install groq sentence-transformers faiss-cpu rank_bm25 numpy
3. Получите API ключ Groq
Зарегистрируйтесь на console.groq.com, создайте ключ.

4. Запустите бота
bash
export GROQ_API_KEY="gsk_..."
python groq_memory_bot.py
При первом запуске создастся пустая память. Файл memory_simple.pkl будет сохраняться автоматически.

5. Общайтесь
Пишите обычные сообщения – Кира отвечает, запоминает факты.

Используйте команды (см. ниже), чтобы управлять памятью.

📋 Команды управления памятью
Команда	Действие
/memory	Показать последние 30 фактов (с временем, доверием, важностью)
/stats	Статистика: количество фактов, категории, размер FAISS, настроение Киры и т.д.
/export	Экспорт памяти в memory_export.json
/import	Импорт из memory_import.json
/clearmemory	Очистить все факты, оставив только системные правила
/clearall	Полная очистка (с подтверждением)
/forget <id>	Удалить конкретный факт по ID
/forget_contains <текст>	Удалить все факты, содержащие подстроку
/trust <id>	Повысить доверие к факту (+0.2)
/distrust <id>	Понизить доверие (–0.2)
/importance <id> <0..1>	Установить базовую важность
/conflicts	Показать противоречия в одной категории
/assoc [id]	Показать ассоциации факта (или все связи)
/exit	Выйти, сохранив память
🧠 Как работает память: внутреннее устройство
Файл simple_memory.py реализует класс SimpleMemoryManager, который:

Извлекает факты – вызывает Groq с системным промптом, получает JSON массив фактов.

Проверяет дубликаты – через косинусное расстояние эмбеддингов (порог 0.85).

Сохраняет в FAISS – асинхронно (чтобы не блокировать диалог).

Обновляет ассоциации – связывает факты, полученные в одном вызове.

Обслуживает поиск – комбинирует FAISS, BM25 и точное совпадение.

Фильтрует релевантные факты – LLM получает топ‑15 кандидатов и строго отбирает нужные.

Управляет временем – TTL для эфемерных фактов, парсинг временных диапазонов из вопроса.

Консолидирует – каждые 24 часа запускается семантическая и категориальная консолидация через LLM.

Следит за состоянием Киры – kira_mood, laconic_mode, инициатива.

В файле groq_memory_bot.py реализован основной цикл диалога, обработка команд, фоновая задача для инициативы, восстановление истории из working_memory, потоковый вывод ответа (с отрезанием <think> ... </think>).

📁 Структура файлов
groq_memory_bot.py – CLI интерфейс, инициализация, диалог, команды.

simple_memory.py – ядро памяти (все методы SimpleMemoryManager).

memory_simple.pkl – сохранённое состояние (pickle).

memory_export.json / memory_import.json – примеры экспорта/импорта.

README.md – это руководство.
